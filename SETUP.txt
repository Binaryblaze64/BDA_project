BDA PROJECT - THREE-NODE HADOOP / SPARK CLUSTER

Run commands from D:\bda_project in PowerShell with Docker Desktop running.

Software: Hadoop 3.4.3, Spark 3.5.9, Java 11, Python 3.10, NumPy 1.26.4.
Docker image: bda-project:3.4.3-spark3.5.9

Architecture:
master: NameNode, ResourceManager, Spark History Server; Spark client driver during jobs.
worker1 and worker2: each runs one DataNode and one NodeManager.
Each worker offers YARN 2304 MB and 2 virtual cores. HDFS replication factor is 2.
Container memory limits: master 1800 MB; each worker 2800 MB.
All three nodes share this computer's physical resources.

Start:
docker compose up -d

Stop while keeping HDFS data:
docker compose stop

Start again:
docker compose start

Wait for HDFS readiness after a restart:
docker compose exec -T master hdfs dfsadmin -safemode wait

Check workers:
docker compose exec -T master hdfs dfsadmin -report
docker compose exec -T master yarn node -list

Dataset (already uploaded, original file unchanged):
hdfs://master:9000/datasets/food/products_500mb_plus.tsv
570666925 bytes; five blocks, two replicas per block.

Check dataset health:
docker compose exec -T master hdfs fsck /datasets/food/products_500mb_plus.tsv -files -blocks -locations

Run the YARN verification (full dataset count and SQL summary, synthetic MLlib test):
docker compose exec -T master bash /cluster/submit-verification.sh

Web interfaces:
HDFS: http://localhost:9870
YARN: http://localhost:8088
Spark completed-job history: http://localhost:18080
Live Spark driver UI: http://localhost:4040 (only while a client job runs)
Some Hadoop UI links use internal container hostnames; use the localhost URLs above.

Persistence:
HDFS data lives in Docker named volumes bda_master-data, bda_worker1-data,
bda_worker2-data. Normal stop/start preserves it. Do not use docker compose down -v
unless you intentionally want to delete the cluster's stored data.
The project and original dataset are mounted read-only inside the master.
No dataset downloads were performed.

Files:
compose.yaml: services, resources, localhost-only ports, storage.
docker/conf/: Hadoop and YARN configuration.
docker/start-cluster-node.sh: process startup and first-time NameNode format only.
docker/submit-verification.sh: Spark YARN resource settings and submission.
docker/verify_cluster.py: verification code.
logs/cluster-verification.log: saved verification output.

This is a local educational cluster with no authentication, exposed only on localhost.
The full pipeline has been implemented and successfully run on YARN.
